01

先给结论：它是什么

当前 Sample 是一套不复用 Forward/Deferred 的纯光追直接光管线。DXR 负责主表面和最终可见性，Compute 负责 Initial RIS、Temporal 与 Spatial Reservoir Resampling，最后只用一个全屏光栅 Pass 做曝光和 ACES 显示。

它具备 ReSTIR DI 的核心闭环：w = pHat / q 初始加权采样、固定大小 Reservoir、时空合并，以及只给幸存候选补一条阴影射线。更准确的分类是原论文 Algorithm 5 的实用有偏实现，而不是带 MIS 校正的严格无偏 Algorithm 6。

阅读边界：“标准 ReSTIR 核心流程”与“严格无偏估计器”不是同一个承诺。当前代码明确没有实现论文 4.3/4.4 节的 MIS 修正，也没有在 Initial RIS 阶段复用上一帧 Visibility。

主流程

Scene Sync → Primary DXR → Initial RIS → Temporal → Spatial → Visibility DXR → HDR StructuredBuffer → ACES Present。

资源策略

BLAS/TLAS、Surface 和 Reservoir 历史全部由 Sample 自己维护；稳态帧在 Graphics Queue 上提交，不调用 WaitForIdle()。

02

数学合同：q、pHat、M 与 W

直接光目标

BRDF、辐射亮度与几何项组成未遮挡贡献；可见性被延迟到最终 DXR 阴影射线。Reservoir 使用未遮挡贡献的亮度作为标量目标函数。

p^(x)=luminance(funshadowed(x))

Initial RIS

候选由 proposal distribution q(x) 生成。候选越匹配目标函数，方差越低；PDF 写错则会直接产生偏色、亮点或能量错误。

wi=p^(xi)q(xi)

03

三个候选域与完整 proposal PDF

候选空间被拆为三个域。CPU 按域总功率和 UI 倍率得到混合概率，GPU 再乘域内 Alias PMF。完整 PDF 是 q(x) = P(D) × q(x | D)，不能漏掉任何一项。

q(x)=PD·qD(x),D∈{Analytic,Emissive,Environment}
ANALYTIC

解析灯

Directional、Point、Spot 全部进入灯光 Alias Table。PDF 为域概率乘灯的离散 PMF，沿用 DSMEngine 现有衰减语义。

EMISSIVE

自发光三角形

权重使用世界面积与自发光功率；选中后在三角形内部连续采样。PDF 还要除以三角形面积。

ENVIRONMENT

环境贴图

经纬度像素权重包含亮度和纬度立体角。选中后像素内抖动，PDF 再除以该像素对应的立体角。

为什么用 Walker Alias：每个候选都能 O(1) 选择离散对象。GpuAliasEntry 额外保存归一化 PMF，是为了让后续 pHat/q 使用真实分布，而不是 Alias 分桶的内部概率。
04

场景转译与 DXR 可见性

加速结构

  • 每个唯一 Mesh 缓存统一顶点、32 位索引与 BLAS。
  • 每个 Submesh 对应一个 DXR Geometry。
  • 实例按稳定 ObjectID 排序；TLAS 拓扑变化时重建，只有变换变化时 refit。
  • Primary 与 Shadow 使用不同 Instance Mask。

材质与 Alpha

  • 不透明实例使用 ForceOpaque。
  • 透明材质进入 any-hit，以基础色 Alpha 和 cutoff 裁剪。
  • 支持双面、法线、粗糙度、金属度、自发光及纹理索引。
  • CastShadow=false 仍可被 Primary 看见，但不遮挡 Shadow。

Primary 输出为什么决定复用质量

GpuSurface 保存位置/深度、法线/粗糙度、反照率/金属度、自发光、运动与稳定实例 ID。Temporal 和 Spatial 所有兼容性判断都依赖这份数据，因此法线、运动向量或稳定 ID 错误会被放大成拖影、漏光或完全拒绝历史。

历史清除：Resize、场景切换、拓扑/材质集合、光源分布、环境或算法参数变化会清空历史。连续相机、物体和灯光运动不会直接清空，而由重投影校验决定保留区域。
05

Temporal 与 Spatial Reservoir Reuse

Temporal：重投影上一帧

motion vector 把当前像素映射到上一帧。只有命中有效、稳定 ID 相容、法线夹角和相对深度都通过阈值、且坐标在屏幕内时，历史 Reservoir 才会进入合并。

Algorithm 4 / 5

Spatial：邻域候选

在半径内随机选择邻居，按同一套表面兼容条件拒绝跨物体、跨深度或跨法线的邻居。每个邻居只带一个代表样本，但保留它的 W × M 信息。

Algorithm 5
wmerge=p^current(ysource)·Wsource·Msource

为什么必须重新评价 pHat

邻居或历史 Reservoir 的代表光源来自另一个表面。合并前要在当前表面重新计算该候选的未遮挡目标值，否则会把邻居的 BRDF、距离和入射方向错误地当作当前像素的值。合并后重新 Finalize，才能得到当前表面的 W。

有偏来源：historyMCapMultiplier 把历史 M 限制在初始候选数的固定倍数内；它能阻止拖影和数值膨胀，但不是严格无偏论文公式的一部分。Spatial 邻居筛选和只保留一个代表样本也会引入工程偏差。
06

最终可见性与 SPP

最终 shade 只给幸存候选发一条 DXR 阴影射线，直接光估计量是：

L^direct=funshadowed(y)·W·V(y)

SPP 的真实语义

samplesPerPixel 表示 1～8 条独立完整 ReSTIR lane。每条 lane 有自己的随机序列、Reservoir 历史、Temporal/Spatial 合并和 Visibility，只有最终结果才平均。

因此它不会把同一个 Reservoir 错误重复放大，但会近似线性增加候选、历史显存和阴影射线开销。

为什么高 SPP 不会自动无噪声

剩余误差可能来自 proposal 不匹配、极亮长尾、时空相关、没有去噪和色调映射。提高 SPP 主要降低独立阴影样本噪声；如果 Alias PDF 或环境立体角错了，应该先修分布而不是无限增加 SPP。

性能判断：Primary 表面通常共享一条主射线；SPP 增长的主要成本来自每 lane 的候选生成、Reservoir 读写和最终 Visibility。可以用 Independent RIS 对照判断噪声来源，再决定提高初始候选、Spatial 邻居还是 SPP。

Debug View

Surface、Normal、Albedo、Source Type/ID、pHat、Reservoir M/W、Temporal/Spatial Accept、Visibility。

排查顺序：Surface/Normal → Source ID 与 pHat → 接受率 → Visibility。

默认参数

32 初始候选；Temporal 开启；历史 M 上限倍率 20；Spatial 2 × 5 邻居；半径 30 px；法线 25°；相对深度 0.1；Alpha cutoff 0.5。

建议的调参顺序

  1. 先用 Independent RIS 调三个候选域权重和初始候选数。
  2. 打开 Temporal，观察静止画面的接受率及运动后的拒绝区域。
  3. 最后打开 Spatial，逐步增加邻居数或 pass。
  4. 法线偏移只用于消除自遮挡；不要用大偏移掩盖错误法线。
  5. 高亮火花优先检查 pHat/q、环境立体角和 Alias PMF。

09

必须保留的实现边界

当前没有实现

  • 论文 4.3/4.4 节的 MIS 校正。
  • Algorithm 6 的严格无偏合并。
  • Initial RIS 阶段的上一帧 Visibility 复用。
  • 无限历史 M 或免费无限 SPP。

工程约束

  • 不复用 Forward/Deferred 的 GBuffer、Lighting、Shadow Pass。
  • 不修改 DSMEngine/Runtime/Graphics/**。
  • 只有最终显示使用全屏光栅 Pass。
  • Reservoir 布局与 HLSL enum 序号由静态断言守护。

如果目标是严格无偏参考实现，需要另行加入 MIS 权重、可见性历史和偏差/方差验证；不能只把 UI 中的历史 M 上限调大。
