## 一页结论

ReSTIR 解决的问题不是“如何用一条光线得到精确光照”，而是“当光源数量巨大、每像素只能承担极少光线时，如何把本帧、邻域和上一帧见过的优质光源样本压缩成一个可继续复用的随机样本”。其核心是三层组合：

1. 用重采样重要性采样（RIS）从一批候选中偏向选择高贡献样本；
2. 用加权 reservoir sampling 只保存一个样本、累计权重和候选数，却仍保持正确的选择概率；
3. 把邻域像素和历史帧的 reservoir 当作“代表大量候选的压缩样本”继续合并。

论文只处理相机首个可见表面上的单次直接光照。候选样本来自发光三角形或环境光，目标函数通常采用“不含可见性”的未遮挡反射贡献；可见性可以在选择后测试并随 reservoir 传播。论文同时给出低偏差的快速变体与代价更高的无偏修正。

最重要的直觉是：reservoir 不是一个普通缓存。它保存的是一个带统计意义的代表样本，`wSum`、`M` 和最终权重 `W` 缺一不可。只复制被选中的光源而不复制或重算这些统计量，会破坏估计器。

## 1. 问题定义

### 1.1 直接光照积分

在相机光线命中的表面点 `x`，直接光照可以写成对光源采样域 `Y` 的积分：

```text
L(x) = integral_Y f(x, y) dy

f(x, y) = Le(y -> x) * BSDF(x, y) * G(x, y) * V(x, y)
```

其中：

- `y` 是光源上的样本，例如一个发光三角形上的点；
- `Le` 是从光源样本朝向接收点发出的辐射亮度；
- `BSDF` 描述材质对入射方向的响应；
- `G` 包含两端余弦和距离平方衰减；
- `V` 是二值可见性，无遮挡为 1，被遮挡为 0。

若直接从概率密度 `p(y)` 取 `N` 个独立样本，普通蒙特卡洛估计为：

```text
L_hat = (1 / N) * sum_i [ f(x, y_i) / p(y_i) ]
```

当 `p` 与 `|f|` 的形状接近时方差低；当场景中有数百万个动态发光三角形时，构造并采样这样的理想分布很困难。

### 1.2 论文的边界

论文明确聚焦：

- 相机首个命中点；
- 一次直接光照；
- 大量动态局部光或发光三角形；
- 屏幕空间邻域与跨帧复用；
- 极少的最终阴影光线预算。

它不是完整路径追踪器，也没有直接解决多次间接反弹、镜面链或离屏世界空间缓存。

## 2. 重采样重要性采样（RIS）

### 2.1 为什么需要候选分布和目标函数

设候选从容易采样的源分布 `p(y)` 生成。我们希望最终样本更接近难以直接采样的目标分布 `pHat(y)`。`pHat` 不必归一化，只要与期望分布成比例即可。

对每个候选计算重采样权重：

```text
w_i = pHat(y_i) / p(y_i)
```

然后在 `M` 个候选中以 `w_i / sum(w)` 的概率选出一个样本 `z`。对应的 RIS 估计器为：

```text
L_hat = [ f(x, z) / pHat(z) ] * [ (1 / M) * sum_i w_i ]
```

第一项把目标函数换回真正要积分的函数，第二项估计目标分布的归一化常数。目标函数不需要等于完整 integrand；只要它在 `f` 非零处不为零，估计器就有正确支撑。

### 2.2 目标函数的实际选择

论文常用未遮挡反射贡献作为目标函数：

```text
pHat(y) proportional to luminance(Le * BSDF * G)
```

不在初始目标中加入可见性，能避免为每个候选都追踪阴影光线。缺点是被遮挡但表面贡献很高的候选仍可能被选中，后续才会发现其贡献为零。论文进一步研究了把已知可见性随样本传播的方式。

### 2.3 一个离散示例

假设某像素随机得到 4 个候选光源，源分布均匀，目标亮度分别为 `1, 2, 7, 0`。忽略共同的源 PDF 因子后，总权重为 10，第三个候选以 70% 概率入选。reservoir 只保留这个候选，但还必须保留总权重 10 和候选数 4，才能在最终估计或下一次合并时恢复这批候选的统计影响。

## 3. 加权蓄水池抽样

### 3.1 最小状态

论文把一批候选压缩成如下 reservoir：

```text
Reservoir R:
    y       当前被选中的样本
    wSum    所有已处理候选权重之和
    M       这个 reservoir 所代表的候选数量
    W       最终归一化权重
```

流式处理权重为 `w_i` 的候选 `y_i` 时：

```text
R.wSum += w_i
R.M    += 1
以 w_i / R.wSum 的概率令 R.y = y_i
```

完成后计算：

```text
R.W = R.wSum / (R.M * pHat(R.y))
```

因此最终贡献可写成 `f(R.y) * R.W`。若 `pHat` 直接取不含可见性的标量贡献，则实现时通常把颜色贡献除以该标量，再乘 `W`；不要把 `W` 再当成普通 PDF 的倒数重复相除。

### 3.2 为什么流式更新仍然正确

当第 `i` 个候选到来时，它先以 `w_i / sum_1^i(w)` 的概率替换旧样本；旧样本以剩余概率保留。递推展开后，任意候选最终被选中的概率都是 `w_i / sum_1^M(w)`。算法只需常数空间，不必保存候选数组，特别适合 GPU 每像素执行。

数值上需要留意：

- `wSum` 可能被极亮样本放大，应使用至少 32 位浮点并检测非有限值；
- `pHat(R.y)` 必须在当前接收点重新计算，不能盲用邻居像素的值；
- `M` 是代表的候选数，不是帧数、邻居数或光线数的随意替代品；
- `pHat=0` 时不能生成有限的 `W`，应把 reservoir 视为空；
- 生产实现可以压缩存储，但正确性参考版本应先保留全精度。

## 4. 合并 reservoir

### 4.1 把一个 reservoir 看成压缩候选集

假设邻居 reservoir `R_q` 代表 `M_q` 个原始候选，选中样本为 `y_q`，归一化权重为 `W_q`。要把它合入当前像素 `x`，论文给出的等效候选权重是：

```text
w_merge = pHat_x(y_q) * R_q.W * R_q.M
```

同时，新 reservoir 的候选计数增加 `R_q.M`，而不是只增加 1。全部 reservoir 合并后仍按当前像素的目标函数重算：

```text
R_new.W = R_new.wSum / (R_new.M * pHat_x(R_new.y))
```

这条公式是 ReSTIR 的核心接口。`R_q.W * R_q.M` 恢复旧 reservoir 所代表候选集的归一化影响，`pHat_x` 则把旧样本重新解释为“对当前像素有多重要”。

### 4.2 不能直接复制邻居权重

相邻像素的材质、法线、距离和光源夹角不同。邻居的 `pHat_q(y)` 并不是当前像素的 `pHat_x(y)`。直接复制邻居贡献或只按邻居亮度混合，会把普通空间滤波误当成采样重用；在高光、几何边缘和小光源附近尤其容易产生偏差和漏光。

## 5. 空间复用

论文在初始 reservoir 之后，从屏幕空间邻域选择若干 reservoir 合并。典型流程为：

1. 当前像素用本地候选生成初始 reservoir；
2. 在给定半径内随机选择 `k` 个邻居；
3. 用深度和法线拒绝明显不属于同一表面的邻居；
4. 对每个合格邻居，在当前像素重新计算 `pHat` 并合并；
5. 可进行多轮空间 pass，每轮读上一轮、写下一轮，避免同一 dispatch 内读写反馈。

论文的低偏差配置常用 `k=5`、半径 30 像素、法线阈值约 25 度、深度差约 10%，并运行两轮；无偏版本为控制额外可见性测试，使用更少邻居和更少 pass。

空间复用把别处发现的好光源传播到当前像素，但也有明显边界：它只看屏幕可见表面；跨深度边缘可能漏光；重复 pass 会让样本支持范围迅速扩大，并使相关性更强。邻居选择使用旋转的低差异序列，通常比固定十字或规则网格更不容易形成结构化噪声。

## 6. 时间复用

### 6.1 重投影与合并

对当前像素，通过运动向量找到上一帧对应表面，把历史 reservoir 当作另一批候选合入当前 reservoir。必须先验证：

- 重投影坐标有效；
- 历史深度与当前重建深度相符；
- 历史法线与当前法线相符；
- 选中光源或发光三角形仍然存在且语义相同；
- 相机切换、分辨率变化、场景大改动时历史已清空。

时间复用能把少量候选跨帧积累成很大的有效候选集，是 ReSTIR 收敛快的主要原因。代价是相关性、拖影和滞后。论文把历史 `M` 限制为当前 reservoir 候选数的 20 倍，以免很久以前的统计量压倒新信息；这是稳定性手段，不是估计器理论必需项。

### 6.2 光源身份必须稳定

历史 reservoir 保存的不能只是“上一帧光源数组下标”。如果 CPU 每帧重新剔除和排序灯光，同一下标可能已经代表另一盏灯。稳健实现应保存稳定 ID，并用当前帧映射表解析；灯光删除、形状变化或采样参数变化还应携带 revision，使旧样本失效。

## 7. 可见性复用

初始候选的目标函数通常不含阴影可见性，因为逐候选追踪光线太贵。选中样本后只需一条阴影光线。论文还提出把已经测试过的可见性随 reservoir 传播：若一个 reservoir 的选中样本已确认被遮挡，可以在复用前丢弃它，从而避免遮挡样本不断扩散。

这是一种实用但需谨慎的优化：历史可见性是在旧接收点、旧几何状态和旧时间计算的。光源或遮挡物移动后，它可能立即过期。实现至少要在最终着色点重新测试可见性；把历史结果用于候选引导时，应把它理解为 proposal guidance，而不是永远可信的真值。

## 8. 偏差从哪里来

### 8.1 朴素复用不再是独立同分布采样

初始 RIS 的候选来自已知源 PDF；空间和时间复用以后，每个 reservoir 的样本来自不同接收点、不同候选集和不同支撑。若仍把它们当作来自同一个分布的独立候选，简单合并会漏掉“这个样本在其他来源下本来有多大概率产生”的校正。

直观例子是：光源只对邻居可见、却不在当前像素原始 proposal 的支撑内。邻居偶然把它传播过来后，当前像素会给它很高目标权重；但反向的候选关系并不对称。多轮复用还会重复统计彼此已经共享过的候选。结果通常是稳定且低噪，但可能偏暗、丢失能量或在边界形成系统误差。

### 8.2 论文的无偏修正

论文把多个 reservoir 的复用视为多重重要性采样问题。对于候选样本，计算它在所有参与 proposal 下的可生成概率，并使用类似 balance heuristic 的 MIS 权重 `m` 分摊贡献。要正确知道某样本是否属于另一个像素的有效支撑，往往还需要额外的目标函数或可见性查询。

因此两种模式形成明确权衡：

- **偏置版本**：少量光线、质量稳定、速度最高，允许可控能量误差；
- **无偏版本**：统计上更严格，但要减少邻居数量和 pass 数来承担额外查询成本，噪声也可能更明显。

“无偏”不等于每帧看起来更好。它只说明期望值收敛到正确答案；有限样本的方差、时域稳定性与重建质量仍需单独评估。论文的实际结论也不是无条件选择其中之一，而是把两条质量/性能曲线都给出。

## 9. 论文完整算法的阅读顺序

把论文算法压缩成 GPU pass，可以按下列顺序理解：

```text
G-buffer / primary hit
        |
        v
每像素生成 M 个灯光候选
        |
        v
Initial RIS reservoir
        |
        +---- 历史重投影、验证、合并
        |
        +---- 邻域采样、验证、合并（可多轮）
        |
        v
对最终选中样本测试可见性
        |
        v
f(y) * W -> 直接光照
```

论文实验的主要配置为：每像素 `M=32` 个初始候选；发光三角形按功率采样；约 25% 候选用于环境贴图；偏置版本每轮取 5 个空间邻居、运行两轮，并在每像素保留多个 reservoir；无偏版本减少到 3 个邻居、单轮、单 reservoir。历史候选数上限为当前候选数的 20 倍。

这里的数值是论文场景与 2020 年硬件下的实验点，不应当直接成为引擎常量。现代实现应分别调节候选数、reservoir 分辨率、空间邻居数和最终可见性光线数，并记录误差曲线。

## 10. 实现细节译述

### 10.1 灯光候选生成

论文场景可包含数百万动态发光三角形。作者按发射功率构建离散分布，用 alias table 常数时间抽取三角形，再在三角形内部采样位置。环境光候选来自单独 proposal。混合 proposal 时，候选 PDF 必须包含“选择哪一种 proposal”的概率；漏掉混合概率会直接导致权重错误。

对解析点光、聚光灯的引擎改写时，采样域与论文不同：离散灯光选择概率是 PDF/PMF 的主体；点光没有面内坐标，面光则还要乘条件位置 PDF。工程里应把“稳定灯光 ID、灯光类型、面内随机变量、源 PDF”作为一个候选的完整语义。

### 10.2 目标函数与着色

作者用 `rho * Le * G` 一类未遮挡量构造目标，其中 `rho` 代表反射响应。目标最好便宜、非负、与最终颜色贡献强相关。彩色贡献压成标量时通常取 luminance；色彩饱和的极端灯光可能让标量目标遗漏某个通道，因此必须保证只要任一最终通道非零，目标就不会错误变成零。

最终着色仍应重新计算完整 RGB BSDF、几何项、发射和可见性。reservoir 中不宜长期缓存完整最终颜色，因为接收点材质与几何会变，复用时也必须按当前像素重算。

### 10.3 数据布局

理论结构很小，但实际还要标识发光三角形及其重心坐标，或灯光 ID 与形状参数。论文使用多个 reservoir 以提高效果。工程上常把离散 ID 和标志打包为整数纹理，把位置随机变量、`wSum`、`M`、`W` 放入浮点纹理；调试版应保留可读格式，并提供显示 selected ID、`M`、`W`、history age 的可视化。

### 10.4 可见性预算

论文在高质量配置下仍把总光线控制在每像素个位数，最高示例约 8 条，而不是为数十个候选逐一追踪。其性能优势主要来自“先用便宜目标筛选，再对极少结果做昂贵可见性”。若实现把每个 candidate 都追踪阴影，虽然可能降低噪声，却已经失去 ReSTIR 的关键成本结构。

## 11. 实验结果如何解读

论文展示的核心不是单一帧率，而是等误差比较：在相近误差下，偏置方案相对当时的基线可获得约 35-65 倍速度提升，无偏方案约 6-60 倍；测试场景最多约 340 万个动态发光三角形，整套直接光照可在约 50 ms 内完成。

这些数字不能直接外推到 UE 5.8、现代 GPU 或 DSMEngine：基线算法、场景灯光类型、BVH 成本、分辨率、材质复杂度和去噪器都不同。可复用的结论是：时空重用可以把每像素极少的局部探索，转化为跨像素、跨帧的大候选池；真正应复现实验方法——固定质量度量、比较误差与 GPU 时间——而不是复现宣传数字。

## 12. 图表阅读指南

原文图像受版权保护，本译述不复制图页。阅读原 PDF 时可按以下问题观察：

- **算法示意图**：候选如何从源分布进入 reservoir，`wSum` 与选中样本如何更新；
- **时空复用对比**：只做初始 RIS、加入空间复用、加入时间复用后，噪声传播范围如何变化；
- **偏置/无偏图**：注意平均能量是否偏暗，不要只看单帧噪声；
- **动态场景序列**：观察新显露区域、运动灯光和遮挡变化后的恢复时间；
- **性能表**：区分候选生成、可见性光线、复用和着色成本，并确认比较的是同等误差而非同等样本数。

## 13. 局限性

论文主动暴露了以下限制：

- 主要在屏幕空间首个可见表面工作，离屏信息不能直接提供复用；
- disocclusion 没有有效历史，会暂时回到低候选数噪声；
- 灯光或遮挡快速变化会让历史样本滞后；
- 朴素复用存在偏差，多轮传播可能积累能量误差；
- 对间接光路径不能直接照搬 DI 合并公式；
- 极强小光源和高度镜面材质会造成重尾权重与 firefly；
- 最终质量仍依赖运动向量、表面一致性判定和去噪。

尤其要注意最后第二点。ReSTIR GI 的复用样本是路径第二顶点，接收点改变会改变面积/立体角测度，需要 Jacobian；原始 ReSTIR DI 在光源面积域复用直接光样本时没有同样的 GI Jacobian。把两种公式混用，是实现中很常见的概念错误。

## 14. 公式检查清单

实现或审阅代码时，逐项核对：

1. 源 PDF 是否包含灯光选择、proposal 混合和灯面位置三个层级；
2. `pHat` 是否非负，并覆盖最终 integrand 的全部非零支撑；
3. reservoir 更新概率是否为 `w / new_wSum`；
4. 初始 `W` 是否为 `wSum / (M * pHat(selected))`；
5. 合并权重是否使用当前像素的 `pHat_current(selected)`；
6. 合并后 `M` 是否累加被合并 reservoir 所代表的候选数；
7. 合并后是否按最终被选中样本重新计算 `W`；
8. 历史是否用稳定 ID、深度、法线和 revision 验证；
9. 最终贡献是否在当前接收点重算完整 RGB 与可见性；
10. 若加入 clamp、visibility guidance 或近似 MIS，是否明确标为有偏策略。
